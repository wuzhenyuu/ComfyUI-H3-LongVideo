# ComfyUI H3 Long Video

主线与定制功能的合并范围、旧口播迁移和支持边界见[功能保留对照表](FEATURE_PARITY.md)。

完整集成版源码与 ZIP：[wuzhenyuu/ComfyUI-H3-LongVideo](https://github.com/wuzhenyuu/ComfyUI-H3-LongVideo)。本版保留 MV／口播／RunningHub，并合入音乐情绪、素材库、批量扩写和恢复功能。所需权重请先看[模型下载与本地存放路径](MODEL_DOWNLOADS.md)，模型和 API 凭据不包含在源码包内。

完整功能合并版：保留 MV／口播本地与 RunningHub 双后端、独立审核与项目恢复，同时加入跨项目素材库、1–4 路批量扩写、Codex CLI、参考视频和本地音乐情绪分析。当前推荐入口仍为下面的 07 MV 与 13 口播；更新记录见 [CHANGELOG.md](CHANGELOG.md)。

朋友测试包请先看[安装与测试说明](FRIEND_TESTING.md)。当前口播种子在K采样器固定，画布只保留一个视频输出，项目下拉旁提供与MV一致的“管理项目”。

MV 与口播共用画布配色、按钮排列和两行进度区。两者均提供 RH API 设置、配置检查、重新分析、分段控制和错误日志下载；本地模式收起 RH 参数。口播面板补齐“停止后续生成”和“打开文件位置”，停止会等当前段完成；继续时复用已完成段。口播保持单图与固定构图，逐段提示词直接在段内编辑。

MV分段审核支持“增加切点”：单击波形选择时间，或在工具栏输入精确秒数，再点增加切点。拆分后两段都须4–15秒，并遵守项目设置的更小上限；不足8秒的片段不能再拆。新增会将当前修改一并保存为草稿，试听并检查两段重新生成的简报后再“保存并确认”。原结果保留为待更新版本，未修改的已完成段继续复用。

## 先选择用途：MV、口播是两张独立画布

|本地工作流|核心节点|画布生成链|
|---|---|---|
|[07 歌曲MV](examples/07_H3MV_本地与RH.json)|MV Generator：分段、审核、任务、预览、重做与合并|MV Prompt Expander、模型/LoRA、Ref2VA、音频零罩、SelfLift、VAE、视频保存|
|[13 口播数字人](examples/13_H3口播_独立窗口_本地展开.json)|Talking Avatar：独立分段、审核、任务、动作选切、恢复与合并|音频/图片加载、提示词/尺寸参数、模型/双LoRA、Ref2VA、种子在标准K中固定、VAE、统一视频输出|

两张本地画布互不包含对方的生成节点。封装的是长音频管理能力，不是整套生成工作流；模型及采样必须执行画布上实际连接的节点。口播提示词、分辨率用独立参数节点编辑，种子直接在标准K采样器设置为fixed；项目记录实际配置供重做和恢复使用。

13口播画布的普通“运行”只准备项目并打开审核，不加载模型采样；审核后从面板启动分段生成。因此新版画布无需四个额外的LazySwitch加载开关。分段控制面板负责合并；同一个视频输出逐段时显示原片，合并后显示完整成片。

当前推荐入口是07 MV和13口播两张画布，两者均可选择本地／RunningHub。RH计算端分别用08 MV和15口播模板；选择RH时本地展开的模型分支不执行。14仅为可选精简RH控制示例。04/05/06/09/10/11是历史参考文件，不是当前安装或新项目的默认入口；不要把04的采样、保存节点与模型说明套用到07/13。

当前口播默认一张图片，由图片确定人物、背景和构图，使用单图固定提示词；`reference_audio`（参考人声）与分段原声分别连接。旧统一节点的 speaking 入口不再保留；需要接续创作时，用13新建 Talking Avatar 项目，复用原素材，保留旧项目和视频。本版没有两种项目状态结构的自动转换器，不能把旧 speaking 项目直接当作MV运行。换图也应新建项目，避免混入旧片。

MV默认接原音频，通过“音频处理”选择“直接使用”或“提取人声”，默认提取；也支持可选 `vocals` 外接人声，连接时优先采用该人声并校验与原曲对齐，最终成片仍保留输入原曲。未连接时沿用所选音频处理方式。Talking Avatar 默认单图与原音，音频处理默认“直接使用”；需要分离时可选“提取人声”。整条音频在创建项目时准备一次并缓存，本地和RH共用参考人声；已有项目使用原保存配置。口播不会自动改写成双图提示词。Use Everywhere启用时，本插件隐藏的参数不会额外绘制自动连接圆点，显示参数时恢复原设置。

本次为功能修复更新；自动化回归和 CPU 转写检查不代表本地画质或真实 RH 调用重新验收。口播当前机制见[TALKING_OVERLAP.md](TALKING_OVERLAP.md)。

MV Generator现可选择**本地／RunningHub**，两种方式共用原有分段审核、切点与素材微调、逐段预览/重做和最终合并。导入[MV双后端工作流](examples/07_H3MV_本地与RH.json)；本地使用画布中展开的模型、Avatar与解码链路。RH模式填写自己有权访问的云端工作流ID，选择区域和实例；云端模板见[RH单段生成工作流](examples/08_H3MV_RH云端生成模板.json)。云端权重、采样、seed和分辨率在RH工作流中调整，本机无需安装云端模型。提示词仍沿用本地MV Prompt Expander，或把segment_prompt接到Ref2VA。

在MV或口播节点点击 **RH API 设置**，选择国内/海外站，在密码框填写Key并保存；随后直接检查配置，无需重启。两类节点共用本机配置，但与提示词扩写API分开。Key保存在ComfyUI用户目录的 `H3LongVideo/runninghub_api.json`，不写入工作流、项目快照或返回给前端；不要分享此用户配置文件。优先使用对应站点的本机Key，未设置时兼容 `RUNNINGHUB_API_KEY` 环境变量；本地生成不需要Key。RH任务号显示在每段审核卡片里，中断后点击继续查询原任务。创建结果未知时先在RH核对并绑定任务ID，不能直接重试；明确失败才手动重建。暂停/停止会等待当前RH任务完成，不影响其他任务。完成段按实际保留长度预览，最终仍由本地FFmpeg裁切合并。详情见[执行与恢复说明](MV_RUNNINGHUB.md)。

用于 MiniMax H3 的长音频分段生成插件。MV Generator 分析歌曲、安排分镜和运镜，由配套扩写节点生成提示词；Talking Avatar 以固定构图、音频驱动和动作续接生成口播。两套节点各自提供分段审核与合并流程。

MV 每段最多 6 张参考图，也可共用项目默认图；歌曲 MV 的素材与扩写功能在下方分别说明。口播保持独立单图工作流，不将 MV 多图设置自动套入口播项目。

## 主要功能

- **自动分段**：根据音频分析结果和目标时长划分片段，支持试听与调整切点。
- **逐段多图素材**：项目默认图与本段自定义图独立管理，每段最多 6 张，可调整顺序并填写用途。
- **跨项目素材库**：管理角色／场景图片和参考视频，导入后保存项目独立快照。
- **批量扩写与 CLI**：MV 可用 1–4 路并发扩写，支持 API、已登录的 Codex CLI、候选预览与人工保存。
- **音乐情绪分析**：可选本地 MOSS-Music，按真实音频分段补充导演简报。
- **独立创作流程**：歌曲MV使用MV Generator和MV Prompt Expander；口播使用Talking Avatar。
- **导演简报编辑**：逐段查看、修改画面任务、声音关系、构图、主体动作和镜头运动。
- **双提示词通道**：人工导演简报（含音乐表达修订）参与 API／Codex 的多图扩写；最终手写提示词则从 `segment_prompt` 原样直连 H3。
- **顺序生成**：自动提交各段任务，支持暂停、继续和失败重试。
- **局部重做与合成**：单独重生成某段、恢复上一版，或使用现有片段重新合成。

## 安装

1. 将本仓库克隆或解压至 `ComfyUI/custom_nodes/ComfyUI-H3-LongVideo`。
2. 使用启动 ComfyUI 的同一个 Python 安装本插件的 `requirements.txt`，沿用当前匹配的 PyTorch／Torchaudio，并确保 `ffmpeg`、`ffprobe` 可用；无需另建环境，也不要盲目降级 Torch。命令示例见[模型下载与本地安装](MODEL_DOWNLOADS.md)。
3. 重启 ComfyUI并刷新前端，按用途导入上面的07 MV或13口播展开工作流，每次使用对应的一张。
4. 按所选工作流安装真实外部节点：07 MV 使用 [SelfLift-Avatar](https://github.com/slmonker/selflift-Avatar)、[ComfyUI-KJNodes](https://github.com/kijai/ComfyUI-KJNodes) 与 [ComfyUI-YCNodes-MiniMax-H3](https://github.com/yichengup/ComfyUI-YCNodes-MiniMax-H3)。13 口播当前使用本插件节点与原生标准 K 链路，无额外第三方生成节点。两者都要求 ComfyUI 具备原生 H3、AV latent、MiniMax 文本编码器、尺寸和视频创建／保存节点，具体名称及支持边界见[节点依赖核对](MODEL_DOWNLOADS.md#当前推荐工作流的节点依赖)。不知道版本是否支持时按节点清单核对，不按画布的旧 `cnr_id` 猜测。
5. 本地生成按[完整模型下载清单与放置路径](MODEL_DOWNLOADS.md)准备所选画布的主模型、LoRA、VAE、文本编码器及可选 latent upscaler，再重新选择实际文件名。RunningHub 的视频权重由云端工作流准备，本机仍需音频处理及所用扩写服务；不要把模型名字相近当作可直接替换。

MV示例将 `segment_material`、六路图片和帧率分别连接到独立扩写、Ref2VA和视频输出节点。口播示例单独连接参考图、分窗原声、Ref2VA及标准K链路。模型、LoRA、VAE和CLIP文件需按本机实际安装选择；采样参数在各自外部节点调整。不要将历史04示例的参数说明当成07/13的当前配置。

MV 首次音频分析按需下载 Faster-Whisper `large-v3-turbo`；当前口播停顿分段不需要 ASR 模型。两类节点选择“提取人声”且缺少权重时，按需下载约 319 MiB 的 HDemucs；“直接使用”不加载分离模型。下载链接、缓存路径及可选 MOSS-Music 完整目录见[模型下载与本地安装](MODEL_DOWNLOADS.md)。

### 分镜提示词生成器：API 与 Codex CLI

节点的“生成服务”可选 `api`（原有默认方式）或 `codex_cli`。旧工作流没有此字段时继续使用 API，节点输出和连线无需改变。

人工导演简报以 `user_director_brief` 参与 API／Codex 的扩写输入，包含用户对音乐表达的修订；它不是最终手写直出。实际素材、音频和时长约束仍生效，人工音乐修订优先于模型情绪估计。只有最终手写 `segment_prompt` 通道绕过扩写。MV 的 RH 路径也传递所选提供方、Codex 模型、推理档位与超时；CLI失败不会静默转到API。范围对照见[功能保留对照表](FEATURE_PARITY.md)。

选择 `codex_cli` 前，在启动 ComfyUI 的同一 Windows 用户下安装并登录 Codex CLI（`codex login`）。CLI 使用现有登录，不读取本插件的 API Key；`CODEX_CLI_EXE` 可指定本机原生可执行文件的绝对路径。无需新增 Python 依赖。

- “Codex 模型”留空时沿用本机 CLI 模型，也可填写模型 ID；“Codex 推理档位”的 `default` 沿用 CLI 配置，其余可选 `low / medium / high / xhigh`。这些选项仅影响本次调用。
- `vision` 按素材顺序将多图附加给 CLI；`text` 仅传分段文字；`manual` 继续使用原手写／导演简报路径。六段 H3 格式校验、图片引用和单镜头约束保持一致。
- 每次扩写使用独立的 `codex exec --ephemeral`，只读沙箱、临时工作目录，不续接上一段会话。超时或 ComfyUI 取消时清理本次子进程树，不自动重试。
- API 与 CLI 的缓存分开；CLI 模型、推理档位或本机配置变化会使旧 CLI 缓存失效。“分段扩写预览 / 编辑”与顺序生成使用同一组节点设置。

切换回 `api` 后，“API 设置与模型选择”及原有模型字段继续按原方式使用。更新插件后重启 ComfyUI，并刷新浏览器加载新增控件。

自动扩写采用 MiniMax H3 Ref2VA 六章节格式，说明正文使用中文；章节名、`<Subject N>`／`<Picture N>`／`<Audio N>`、任务类型、保留关系标记和 `[Shot 1]` 保留固定语法。每段为一个连续镜头，校验真实生成时长、标签定义与引用、保留关系、画面类型及声音限制。MV演唱沿用工作流实际接入的人声参考，不能仅凭画面类型虚构音频槽；氛围与空镜不请求口型。最终仍配回原音轨，两个声音汇总字段为 `N/A`。

提示词生成与校验不再设置 15 秒硬上限。模型按本段 `generation_seconds`（`generation_frames / 24`）大致安排动作、运镜和结尾，可使用开场、随后、结尾等相对顺序，无需逐秒卡点；名义 15 秒因帧数取整略超也可正常扩写。时长仍须是有限正数，且与实际帧数一致。此调整仅影响提示词层，实际视频分段、采样参数及参考视频输入限制仍按各自工作流执行。纯文本扩写不查看图像或试听音频，只能采用素材说明与简报已经给出的细节。

API、CLI、批量候选及预览编辑保存共用校验；不合规响应不会写入成功缓存，规则更新后旧缓存不再按当前结果复用。已保存人工内容不会被自动重写。独立的 `segment_prompt` 手写直出通道继续原样传递。

### 素材库与批量操作

在审核面板现有素材区点击“从素材库选择”，可按角色／场景分类搜索、上传、编辑信息、换图、删除至回收站或恢复。已有项目素材时选择追加或替换；选中的素材导入为项目副本，再沿用项目默认／本段自定义及 `@图N` 的图号规则。每次最多使用六张，库中的图片版本与项目快照相互独立。

在分段扩写预览中勾选分段后点击“批量扩写”。并发可选 1、2、3、4，默认 2；成功结果先进入候选区，预览或编辑后“保存选中成功结果”统一写回；保存不会自动开始视频生成。相同输入复用有效缓存；重生成保留旧提示词历史。单段、批量、API 和 CLI 等入口共享最多四路模型调用；较高并发会同时占用更多服务额度，实际速度取决于提供方限流与模型响应。批次取消不影响其他项目及 ComfyUI 视频任务。关闭面板可继续执行，重开后查看；服务重启的未完成批次标为中断，由用户选择续跑。

审核弹窗可拖动标题栏移动，方向键移动、`Home` 居中；默认素材区保留展开／收起，窄屏自动改为纵向布局。

### 继续后续生成与仅生成所选段

审核窗口顶部新增“继续后续生成”：从首个未完成或失败段继续，保留所有已有成功视频，包括标为“待重生成”的旧结果。中断后留在“替换前结果”的成功视频会先校验、恢复，再跳过。缺失、损坏、帧数不足或保留片段尺寸不一致时会明确提示，要求单独处理该段，不能静默重跑旧片。

“生成指定段”下拉框可选择任意分段，再点“仅生成所选段”。只处理这一段，完成后停止，不自动跑后续或合成；选中已有视频时会提示重做，并保留旧视频直到新结果成功，失败则恢复旧结果。

继续和单段运行另存本次工作流快照，原 `queue_snapshot.json` 保留。继续合成可以包含保留旧片，“待重生成”和成片旧设置提示仍保留，用来说明它们尚未按当前设置重做。“开始顺序生成”继续按当前设置处理待更新片段。

更新后需重启 ComfyUI 并刷新。新按钮会核对后端能力和项目版本；旧服务未加载此功能时禁用新入口，防止将“继续”误当作普通启动。

### 参考视频：素材库与三个输出

参考视频目前用于本地生成。现有 RunningHub 模板没有已验证的视频上传与 Ref2VA 视频绑定链；选择参考视频后运行 RH 会在扩写、上传或创建任务前明确提示，保留素材及旧片。普通无视频 RH 流程不变；已有付费任务仍按原任务 ID 恢复查询。

审核面板的“项目默认参考视频”可上传视频或从跨项目素材库选择；各段可继承默认组合，也可独立改为自定义。每段最多 3 个视频，每个源视频须为 2–15 秒，组合总时长不超过 15 秒。视频仅用于运镜、节奏和动作参考，不使用原声，也不替换人物／场景图片和项目原音轨。可在说明中使用 `@视频1` 等引用，重排时引用随文件身份调整。

长视频节点保留原有 0–12 号输出，在末尾追加 `video_1`、`video_2`、`video_3` 三个 `IMAGE` 输出（13–15），分别连接 H3 参考条件节点的 `ref_video_0`、`ref_video_1`、`ref_video_2`。它们是 24fps 视频帧序列，未选中的输出为 `None`；顺序生成会按当前分段绑定实际视频并移除空槽，不接入 `ref_video_audio_*`。旧画布加载时仅追加新输出，原连线编号不变。

上传保留原文件和真实源时长；进入 H3 前才按 24fps 和参考画布尺寸上限解码。非整秒视频向下取整至整帧，误差小于一帧，三段归一总长不超过 15 秒。H3 原生节点还会按当前生成帧数和 `17k+5` 网格截取参考，因此界面显示的源时长不代表模型一定逐帧使用完整视频。

图片身份与视频动作分别定义；扩写的视觉模式会读取每个视频的带时码抽样联系图，纯文本模式只使用已填写说明。抽样图不视为额外的 `<Picture N>`，视频按官方 `<Video N>`／Subject 动作来源规则引用，任务类型仍为 `reference generation`。正文中文是本地约定；官方 Ref2VA 指南要求英文正文，固定六章节及标签保持其格式。

依据：[MiniMax H3 模型输入规格](https://github.com/MiniMax-AI/MiniMax-H3)、[官方 Ref2VA 指南](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)。官方托管 API 使用 `video_url`，另有 50MB、编码与尺寸等文件限制；本插件连接本地 ComfyUI 的帧接口，采用本地 FFmpeg 解码兼容，二者不能混用。详见[官方 API 输入要求](https://platform.minimax.io/docs/guides/video-generation)。

MV 首次分析会按需下载 Faster-Whisper `large-v3-turbo`；选择“提取人声”时还会按需准备 HDemucs。后续分析优先复用本地文件，下载链接与离线迁移方法见[模型下载与本地安装](MODEL_DOWNLOADS.md)。

### 本地音乐情绪分析

审核面板可点击“分析全部音乐情绪”，或在分段卡片点击“分析本段音乐情绪”。开始前会保存当前切点和简报；分析使用 `audio/source.wav` 的真实分段区间，结合旋律、节奏、音色、演唱和 ASR 候选歌词。成功后，在该段导演简报中补充情绪标签、强度、变化趋势和表达依据，原有人工正文、手写 H3 提示词与人工扩写保留。后续单段／批量扩写和画布生成均读取补充后的简报。

分析模型为 [MOSS-Music-8B-Instruct](https://huggingface.co/OpenMOSS-Team/MOSS-Music-8B-Instruct)，使用启动 ComfyUI 的同一个 Python 环境；依赖见本插件 `requirements.txt`，沿用 ComfyUI 已安装的 PyTorch／Torchaudio。模型放在：

```text
ComfyUI/models/moss_music/MOSS-Music-8B-Instruct/
```

需要完整的四个权重分片、索引、配置、处理器、tokenizer 和模型代码；固定发行修订为 `fce7f8304e96cc2d3398b8106456cbb2ecec3139`，权重约 16.9 GiB。完整目录下载命令、所需文件树和授权说明见 [MOSS-Music 安装清单](MODEL_DOWNLOADS.md#3-moss-music手动下载完整模型目录)。下载完成后推理只读取本地文件，不自动联网；不要只复制 `.safetensors`。

一次只运行一个本地情绪任务。ComfyUI 队列和 H3 顺序生成任务均须空闲，插件通过原生队列标记释放缓存模型，再用同一 Python 启动推理子进程；每批只加载一次模型，逐段处理，结束或取消后进程退出。关闭审核窗口不会取消后台分析，重新打开可继续查看进度。已有服务未加载该功能时，按钮禁用并提示重启 ComfyUI、刷新页面。

相同原音、精确切点、歌词、模型和分析规则复用结果；修改范围或歌词后旧分析失效。分析过程中若依据发生变化，结果保留为候选，不覆盖当前简报。输出强度 `0–5` 是模型的主观估计，不是校准概率；听不清的歌词、短片段和混合情绪仍须试听复核。

#### 音乐情绪的显存与速度

情绪分析一次提交全部所需分段，同一批次仅加载一次模型、构建一次词表元数据，按段顺序处理。它与提示词扩写的 1–4 路并发是两个阶段；单张显卡不会并行加载多份 MOSS-Music。

模型加载后和每段结束会释放本进程未使用的 CUDA allocator 缓存，活跃权重保留。日志区分 allocated／reserved 与峰值，并记录加载、词表、约束、生成 token、中文转换耗时。一次实测中 allocated 约 16.9 GiB 保持不变，reserved 从约 34.0 降至 17.1 GiB；这是未用缓存释放量，不是模型权重量化或所有设备的保证。

默认仍保留完整十字段和 1536 输出上限。节奏中的 BPM 规范为“拍/分”，数字不变，避免把合法单位误判为中文转换失败。首次模型加载仍有开销，整体速度随显卡、音频和输出长度而变；不要把缓存命中的耗时当作首次推理速度。

### 从旧版升级

歌曲视频使用MV Generator和MV Prompt Expander；旧长视频节点的口播入口已移除，口播改用Talking Avatar。节点ID保留，旧默认标题会在界面加载后更新，用户自定义标题保留。旧口播项目和视频不会删除，也不会自动改成唱歌任务。

更新插件后重启 ComfyUI，并刷新浏览器页面。建议重新导入本仓库的新版示例：旧示例的输出槽位与扩写节点不适用于当前接口，仅替换插件文件不会自动修好旧画布。保留旧工作流副本，不要直接覆盖自己的采样设置。

项目与成片统一保存在 `ComfyUI/output/H3LongVideo`，其下分为 `口播` 与 `MV`；各分类内包含 `projects`、`final_videos` 和运行缓存。API 设置和导演规则仍在 ComfyUI 用户目录下的 `H3LongVideo`，模型在 ComfyUI 模型目录中。重新安装插件时保留这些数据；不要同时在 `custom_nodes` 留下多份本插件副本。

升级时，旧 `output/H3TalkingRH/projects` 口播项目和 `output/H3LongVideo/projects` MV 项目仍可直接列表、打开、继续、预览和管理；原片、成片与任务 ID 原地保留，不自动搬迁。新项目使用分类目录，旧项目补合并的成片也写入新的对应分类。不要通过重新分析或删除旧目录解决升级后的失败段。

若旧版口播停在“各段完成，待合并”，打开原项目点击“仅重新合并”即可；新任务在最后一段完成后会自动合并。MV 扩写会校验每张参考图的来源关系，双图不强制两个 Subject；已在保留关系写明的来源可自动归入定义区。转写使用内部 WAV 数组输入，兼容旧 Faster-Whisper 与 PyAV 19 的参数变化，不替换全局 PyAV 接口。

MV 演唱的人声来自当前段的单一音频通道。扩写正文漏写 Audio 1 定义或摘要引用时，由工作流协议补齐，不要求重新抽取提示词。更新后重试失败段会先尝试修复同一缓存标识下的失败正文，能修复就直接复用；未接入的 Audio 2 等引用仍会拦截。已完成的片段保持，修复音频引用不等于重新分析歌曲。

扩写规则负责创作要求，插件统一规范六字段与引用标签：常见标题、括号、全角、HTML 转义和六字段 JSON 写法会规范为 H3 文本；图号、来源用途和分镜内容保留。空白/占位正文、未定义主体、越界或未接入引用以及截断/过滤返回会在提交视频前拦截。开始生成前会离线检查待生成段的 @图 编号，不额外调用扩写接口。`ref2va_performance_rule.txt` 是手工兼容模板；节点运行规则位于 `expansion.py`，不自动读取该模板。

## 快速开始

以下步骤说明 MV；口播请使用上方 13 工作流及 [TALKING_OVERLAP.md](TALKING_OVERLAP.md) 的独立分段说明。

### 1. 准备素材

加载完整歌曲，将其连接到 **MiniMax H3 · MV Generator** 节点的 `audio`。节点的“音频处理”可选择提取人声或直接使用已准备的干声，项目创建时处理并缓存一次。

先设置 `target_seconds` 与 `max_seconds`，再点击 ComfyUI 的“运行”，完成音频分析并打开分段审核面板。下文的图片上传和逐段编辑都在这个面板中进行。

在分段审核面板上传参考图，并按图片顺序填写素材说明。示例已把长视频节点的图片输出接到 **MiniMax H3 Reference To Video**；无需另接“加载图像”节点。例如：

| 素材组合 | 素材说明示例 |
| --- | --- |
| 一张带背景的人物图 | 图1是人物和背景的完整参考图。 |
| 人物图＋场景图 | 图1是人物，图2是场景。 |
| 人物三视图＋场景图 | 图1是同一个人物的三视图，图2是场景。 |

每段只提供实际需要的图片即可；顺序生成会移除空图片槽位。需要全身镜头时，建议提供包含完整服装与双脚的人物参考。

### 2. 设置项目默认图与本段自定义图

1. 在审核面板的“项目默认参考图”中上传最多 6 张图片并填写用途说明。默认图只需上传一次；该区域可以收起，收起不影响分段控件。
2. 每段选择“使用项目默认”或“本段自定义”。选择自定义时，为该段单独上传、排序最多 6 张图并填写素材说明，例如“图1是人物，图2是场景。”；图号按该段缩略图顺序排列。
3. 点击“保存并确认”后，顺序生成只向 H3 提交当前段实际存在的图片，并移除未使用的参考图输入。修改默认图只影响继承默认的分段，不会覆盖本段自定义图；修改有效素材会使受影响片段等待重新生成。

### 3. 设置分段与镜头

| 参数 | 作用 |
| --- | --- |
| `target_seconds` | 每段的目标时长，优先在不超过目标120%的范围内找句尾和人声低谷；目标5秒通常得到4–6秒片段。为完整覆盖音频且不留下不足4秒的尾段，必要时适当放宽，但不会超过`max_seconds`。 |
| `max_seconds` | 单段允许的最长时长。 |

歌曲MV每段安排一种主要运镜，人物可随表演和镜头移动偏离画面中心。口播的固定构图和动作续接由Talking Avatar独立负责。

“运镜规则：查看与修改”用于调整歌曲MV允许的景别、机位角度和不同音频能量下的运镜候选；多图提示词扩写节点负责将导演简报、音频阶段和分段素材转换成视频提示词。

### 4. 分析并确认

首次点击 ComfyUI 的“运行”，插件会分析音频并打开分段审核面板。

1. 顶部“当前试听”可在 **原曲 / 人声** 之间切换，试听当前选中的分段；每段卡片上的播放器播放该段原曲，前奏、间奏和伴奏段也能正常试听。两个播放器都可以拖动进度条，用来检查切点是否落在气口或句尾。
2. 查看“本段画面”类型，以及导演简报中的画面任务、声音关系、开场构图、主体动作、镜头运动和结束构图，按需修改。
3. 点击“保存并确认”。
长音频可先点击波形选中分段，再点“当前段”或“切点附近”放大。拖动彩色切点线调整时间，用下方滑条横向浏览，点“全曲”恢复总览。也支持双击局部放大、Ctrl / ⌘ + 滚轮缩放和 Shift + 滚轮横移。放大至单段时长范围内会加载原曲与人声的精细波形；已有项目无需重新分析。点击波形不会自动滚动到分段卡片。

修改分段时长或运镜规则后，点击节点上的 **“重新分析并分段”**，让新设置生效。

需要拉长某段时，点击波形上的彩色切点线，再点 **“删除切点”**，把两侧片段合成一段。工具栏显示将删除的时间及合并后时长，合并段须为4–15秒且不超过项目设置的最长时长。也可选中片段后删除其末尾切点，选中最后一段时对应前面的切点。合并沿用前段图片和画面类型，清除旧扩写/直写提示词并重建简报；后段配置与旧结果记录保留，其他未修改片段继续复用。操作保存为草稿，试听并检查简报后再“保存并确认”。

目标时长不代表精确等长切割。普通分段至少4秒，整条音频不足4秒时保留单段；若所设最长时长使完整划分不可能（例如6秒音频要求每段4–5秒），会提示增大最长时长。词界或强制回退切点仍需试听检查唱音拖尾；旧项目不会因升级而自动重新分段。

### 5. 生成与导出

确认分段后，点击审核面板的 **“开始顺序生成”**，或运行整张工作流。插件依次生成各段视频，完成后自动合成并配回原音频。

07 MV 和13口播默认均使用原生 `CreateVideo → SaveVideo`，不需要 VHS。自行搭建或参考历史04时，也支持 VHS 分段保存：

- **VHS Video Combine**：仅历史04或自建VHS分支，需要另外安装 [ComfyUI-VideoHelperSuite](https://github.com/Kosinkadink/ComfyUI-VideoHelperSuite)。
- **ComfyUI 原生创建视频 → 保存视频**：解码图像接 `CreateVideo.images`，长视频节点的 `original_audio_padded` 接 `CreateVideo.audio`，再将 `CreateVideo` 的视频输出接 `SaveVideo.video`。建议保存格式用 `auto` 或 `mp4`、编码用 `auto` 或 `h264`。

顺序生成时，插件自动为所选保存分支绑定项目分段文件名前缀和 **24fps**，VHS 自动开启 `save_output`；无需为了换保存节点重新分析音频。自动绑定只作用于提交的分段任务，不修改画布或其他输出节点，编码、画质等设置仍沿用所选节点。原生链路的 MP4、WebM、MKV 分段都可收集并合成，最终成片统一为 MP4。H3 分段时间线仍以 24fps 计算，不支持改成其他帧率后直接拼接。

画布可以保留多个视频输出；开始顺序生成或重新生成本段时，如有多个连接到 H3 生成链路的可用输出，会弹窗选择本次分段保存节点，仅执行选中的分支。未连接或属于其他图像链路的输出不参与选择。

VHS 的 `frame_rate` 已转为连线输入时，数字输入框可能不再显示；可检查是否接着长视频节点的 `fps`，这本身不表示帧率参数丢失。如 VHS 确实无法使用，可切换上述原生链路。更新插件后请重启 ComfyUI 并刷新浏览器。

最终成片保存在：

```text
ComfyUI/output/H3LongVideo/MV/final_videos
```

项目音频和分段视频保存在：

```text
ComfyUI/output/H3LongVideo/MV/projects
```

## 暂停与修改

- **暂停／停止后续生成**：当前片段完成后暂停提交新任务。
- **继续生成**：生成设置未变时复用已完成片段；改变生成工作流参数后，顺序生成会将受影响的旧结果标记为待重生成。
- **重新生成本段**：使用当前画布设置重做所选片段；新版本成功前保留旧版本。
- **恢复上一版**：恢复该段上一次成功的视频。
- **仅重新合成**：使用现有片段合成成片，无需重新生成视频。

修改某段导演简报或手写提示词会将该段标记为待重生成；调整切点会影响切点两侧的片段，需要重新确认分段。需要重新划分段数时，调整时长参数后重新分析。

## 提示词扩写

示例工作流的文本连接为：

```text
导演简报与多图素材 → H3LVPromptExpand → PreviewAny → H3 视频提示词
```

歌曲MV的镜头规划来自本地导演规则；`H3LVPromptExpand` 按当前段素材、导演简报和所选 `vision`／`text`／`manual` 模式生成提示词。模型服务设置保存在本机用户目录，密钥不进入工作流或项目快照。扩写结果可在分段预览中检查，必要时逐段编辑。

### API 兼容与超时设置

“API 设置与模型选择”使用 **OpenAI 兼容 Chat Completions**：填写基础地址（通常以 `/v1` 结尾）、对应 API Key 和服务实际支持的模型名称。插件在地址后追加 `/chat/completions`；模型列表使用 `/models`，不提供模型列表的服务仍可手动填写模型。多图扩写还要求模型支持 `image_url` 输入，纯文本模型可用 `text` 模式。

- **等待超时**：默认 300 秒，可设为 10–3600 秒。这是连接／读取数据的等待超时，不是整个生成任务的总时限。旧配置无需重填密钥，新选项自动使用默认值。
- **响应方式**：默认普通 JSON；服务支持 `stream` 时可选流式 SSE。插件汇总正文后再校验并保存；不会把思考内容当作提示词，也不会保存中断的流式半成品。服务返回普通 JSON 时仍可解析。
- **思考参数**：默认只自动适配已知 Qwen 混合思考型号及接口：百炼／QwenCloud／OFOX 使用对应型号的原生参数，OpenRouter 使用网关参数。裸名称与 `qwen/` 名称均可识别，但不改写模型名称。未知服务、其他型号及仅思考模型不注入猜测字段；可选“遵循服务默认”停用自动适配。
- **额外请求参数**：高级设置接受 JSON 对象，按服务文档填写，覆盖自动参数；`null` 表示移除字段。例如未知中转服务明确支持时可填 `{"enable_thinking":false}`；采用新 Token 参数的服务可填 `{"max_tokens":null,"max_completion_tokens":8192}`。不能覆盖模型、消息素材、`stream`、地址或密钥。参数仅保存在本机；影响生成内容的参数变化会更新扩写缓存标识，单独修改超时或响应方式不清除缓存。

API 失败会区分超时、DNS／连接／TLS、HTTP 状态、服务端错误与 JSON／SSE 格式错误，并显示等待设置和请求耗时；不输出密钥或原始请求素材。**不自动重试**：客户端超时不代表服务端没执行或没计费，确认服务状态后再手动重试。

已知思考参数依据：[百炼混合思考说明](https://www.alibabacloud.com/help/zh/model-studio/deep-thinking)、[Qwen-Omni 独立参数](https://www.alibabacloud.com/help/en/model-studio/qwen-omni)、[OpenRouter reasoning 参数](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)。新型号或不同中转服务请优先核对其文档，必要时使用额外请求参数，不依赖名称猜测。

此兼容层面向 Bearer API Key 鉴权、标准 `/chat/completions` 路径的服务，不代表所有模型都支持多图、思考关闭或所有额外参数；原生 Anthropic／Gemini、仅 Responses 的接口，以及采用部署路由和其他鉴权方式的服务不在此接口范围。更新后重启 ComfyUI 并刷新浏览器，原工作流连线和采样设置无需更改。

自行搭建工作流时，将 `segment_material` 接入插件的“MiniMax H3 · MV Prompt Expander”，再把生成结果接入 H3 提示词输入。若使用外部工具写提示词，可在分段界面填写“手写提示词”，将长视频节点末尾的 `segment_prompt` 直接接入 H3 `prompt`；该接口不会改写、校验或回退。H3 的 `prompt` 同时只能选择一条连线。顺序生成工作流保留一个 `H3LVUnified` 节点，输出可选 VHS Video Combine 或原生 `CreateVideo → SaveVideo`。也可在画布上将 `filename_prefix` 接到保存节点、`fps` 接到 VHS 的 `frame_rate` 或原生创建视频的 `fps`，明确显示分段保存连接。

## 报错日志

出错后可点击 **H3 长视频节点上的“下载错误日志”**，把下载的 `H3LongVideo-errors.log` 发给维护者。更新插件后需重启 ComfyUI 并刷新浏览器，按钮才会出现。

日志自动保存在：

```text
ComfyUI/output/H3LongVideo/MV/logs/errors.log
```

- 覆盖音频分析、语音识别入口、提示词扩写、逐段提交／生成、视频合并、插件 HTTP 接口及主要前端操作错误；记录时间、阶段、异常堆栈，以及可获取的项目、分段、任务和失败节点信息。逐段生成会从 ComfyUI 任务历史提取原始节点错误，不再只能看到通用失败提示。
- UTF-8 文本，每行一条 JSON 错误记录。单文件约 2 MiB，最多保留 `.1`、`.2` 两个轮转备份；下载按钮按时间顺序合并这三个文件。尚未发生错误时不会创建日志，下载会提示“尚未记录错误”。日志只覆盖更新后发生的错误，旧报错无法自动补全。
- 不主动记录 API 请求正文、完整工作流、节点输入输出或图片／音频数据；对已配置 API Key、常见凭据、URL 和内联数据尽力脱敏，并截断过长异常。第三方异常文字可能包含路径或其他私密内容，**分享前仍请检查**。
- 日志失败不改变原始错误、生成结果或重试策略；不会自动重试 API。它不是 ComfyUI 全局日志，不收集无关工作流错误，ComfyUI 启动／插件导入失败仍需查看启动控制台。

语音识别子进程的详细输出仍在 `output/H3LongVideo/MV/projects/<项目ID>/state/asr.log`。遇到 ASR 报错时，建议一并提供这个文件。`state/segments.json` 中的错误状态也继续保留。

## 使用建议

- MV Generator面向单人演唱MV；口播使用Talking Avatar；建议先生成少量片段，确认素材与模型配置合适。
- 唱歌识别可能出现错字或切点偏差，生成前应试听分段。
- 参考图尽量提供清晰、完整的人物与场景信息。上半身参考中的下装可能由模型补全。
- 景别、运镜幅度、服装和场景保持由生成模型实际执行，需检查成片。片段之间采用剪辑衔接，不保证无缝长镜头。
- 保留项目文件夹可继续重做片段和重新合成；只需交付成片时，导出最终 MP4 即可。
